# Stakeholders

| Stakeholder | Why they matter | Main need | Main concern |
|---|---|---|---|
| Student | Primary user | Useful and realistic weekly plan | Wrong priorities or lost privacy |
| Instructor | Creates course expectations | Students receive accurate task information | Agent invents deadlines or instructions |
| Department / owner | Sponsors or evaluates the system | Useful project with clear scope | Cost, quality and compliance |
| IT / Security | Maintains access and integrations | Safe authentication and data handling | Credential leakage or excessive permissions |
| Calendar / data service | External dependency | Well-formed requests and allowed access | Rate limits, outage, permission scope |

Primary stakeholder: Student, because the student directly uses the product every week.

Secondary stakeholders: Instructor, Department / owner, IT / Security, and Calendar / data service. They may never use the interface, but they still affect the system or are affected by it.

## Raw needs

- Student wants urgent deadlines visible.
- Student does not want the agent to edit the calendar automatically.
- Instructor wants course deadlines represented accurately.
- IT wants minimum permissions for external services.
